# ztok

ztok 是 Project Z 的无损文件压缩器。它把 Gemma 4 的 4,096 个词条编进程序，让压缩器和解压器在读到文件的第一个字节前就拥有同一份词典。文本和代码可以引用这些词条，结构化二进制可以使用局部词典或按格式重排字段。所有数据块最终都由 Zstandard 压缩。

## 安装与使用

需要 Rust 1.88 或更新版本，以及提供链接库的 libzstd 1.4.0 或更新版本。在 Debian / Ubuntu 上，开发包名为 `libzstd-dev`。编译后的程序链接系统 libzstd，正常构建和运行都能离线完成。

```sh
git clone https://github.com/LIghtJUNction/ztok.git
cd ztok
cargo build --release --locked

./target/release/ztok c notes.md notes.ztok
./target/release/ztok d notes.ztok restored.md
cmp notes.md restored.md
```

默认压缩等级为 3，支持 1–19。加上 `--best` 可以在同一等级下试压适用的编码，保留完整字节数最少的一种。输入或输出写作 `-` 时使用标准流。路径输出会保留已有文件，解码失败时会丢弃暂存结果。流式输出会立即交付已验证的数据块，调用方应检查退出状态。

```sh
ztok c --best --level 8 main.rs main.ztok
printf '这里有一行 UTF-8 文本。\n' | ztok c - - | ztok d - -
```

## 压缩路径

默认模式会读取文件内容选择编码。默认模式每块最多 4 MiB，`--best` 放宽到 16 MiB，让较大的网页脚本能在同一块内引用相隔较远的内容。切块时允许一个 UTF-8 字符整体留到下一块。解压器依据归档标记选择逆变换，文件名和扩展名均不参与判断。

| 输入 | 默认处理 |
| --- | --- |
| ≤2 KiB 的 UTF-8 文本、代码或标记 | 使用 45,504 字节的常驻 zstd 词典，覆盖 Gemma 词条、源码和 HTML 片段。短文件也能立即引用已有字节串和熵编码表。 |
| 2 KiB 至 256 KiB 的文本 | 贪心匹配最长 Gemma 词条。替换能节省至少 1/8 的原始字节时，使用专门按词元流训练的 8,193 字节 zstd 词典；其余使用文本词典。 |
| 大于 256 KiB 的文本块 | 默认直接使用 zstd，省去逐词元扫描。 `--best` 仍会比较两种内置词典、原始词表历史、词元流压缩及普通 zstd。 |
| GNU gettext MO 翻译目录 | 对字符串描述表的偏移量取差，并将长度和差值按字节位置重排；字符串正文照原样交给 zstd。 |
| 受支持的 x86-64 ELF 程序 | 在可执行段中可逆地重写相对调用和跳转的四字节操作数，使指向同一位置的值更容易重复。 |
| 其他二进制 | 对可能含重复对齐字段的数据，比较附带局部词典的压缩结果与普通 zstd。已识别的压缩格式直接使用 zstd。 |

例如词表的第一个词条是带前导空格的 ` the`，在词元路径中四个字节用单字节 `0x80` 表示。最常用的 61 个词条占一个字节，其余占两个。字符、空白和字节顺序均可还原。文本词典与词元词典分别训练，因为普通 UTF-8 和词元编号的字节分布不同。正常构建直接读取仓库中的文本资产。[Gemma 词表](data/README.md) · [文本词典](data/preset-v2.md) · [词元词典](data/token-preset-v2.md)

二进制的局部词典最多收录 383 个重复的四字节对齐字段。前 127 个编号占一个字节，其余占两个。每块分别保存所需词典，比较大小时计入这些字节。

## 格式与兼容性

版本 0.2 可以直接解压版本 0.1 的归档。新生成的单块归档采用紧凑格式。普通 zstd 模式直接输出含内容长度和校验和的标准帧，因此也可用系统 `zstd -d` 解开。专用编码增加一个固定的版本标记，原始长度仅在词元或动态字典变换需要它时写入。内置词典随程序分发。多块文件以 `5a 54 4b 02` 开始，随后是长度前缀和独立块，零长度标记文件结束。解压任一受支持的归档都可以使用 `ztok d`。

`--best` 将相同等级的普通 zstd 纳入每一块的候选。对不超过 16 MiB 的独立文件，它写出的完整归档不大于本库按相同参数生成的一个原生 zstd 帧。更大的文件有多个独立块，原生 zstd 用一个连续上下文压缩整份文件时可能得到更小的结果。默认模式通过减少试压换取速度。

Rust 库提供 `compress`、`compress_best` 和 `decompress`，以及对应的 `compress_stream`、`compress_best_stream` 和 `decompress_stream`。没有第三方 Cargo 依赖，运行时依赖系统 libzstd。
