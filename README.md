# ztok

ztok 是 Project Z 的无损文件压缩器。它把 Gemma 4 的 4,096 个词条编进程序，让压缩器和解压器在读到文件的第一个字节前就拥有同一份词典。文本和代码可以引用这些词条，结构化二进制可以使用当前块自己的词典。所有数据块最终都由 Zstandard 压缩。

## 安装与使用

需要 Rust 1.88 或更新版本，以及提供链接库的 libzstd 1.4.0 或更新版本。在 Debian / Ubuntu 上，开发包名为 `libzstd-dev`。编译后的程序链接系统 libzstd，正常构建和运行都能离线完成。

```sh
git clone https://github.com/LIghtJUNction/ztok.git
cd ztok
cargo build --release --locked

./target/release/ztok c notes.md notes.ztok
./target/release/ztok d notes.ztok restored.md
cmp notes.md restored.md
```

默认压缩等级为 3，支持 1–19。输入或输出写作 `-` 时使用标准流。路径输出会保留已有文件，解码失败时会丢弃暂存结果。流式输出会立即交付已验证的数据块，调用方应检查退出状态。

```sh
ztok c --level 8 main.rs main.ztok
printf '这里有一行 UTF-8 文本。\n' | ztok c - - | ztok d - -
```

## 压缩路径

每块最多 1 MiB，独立选择编码。文本检查依据实际字节，支持无扩展名的文件。UTF-8 字符跨越 1 MiB 边界时，最多三个字节会留给下一块。

| 输入特征 | 编码 | 解压所需信息 |
| --- | --- | --- |
| 不超过 2,048 字节的 UTF-8 文本或代码，词元替换至少节省 1/16 的原始字节 | 贪心匹配最长词条。排名前 61 的词条占 1 字节，其余占 2 字节，再压成 zstd 帧 | 内置词表和文件中的词典指纹 |
| 更长的文本、代码或低匹配度短文本 | 把同一份词表拼接成 29,110 字节的 zstd 共享历史，高频词靠近末端 | 同一内置词表 |
| 含重复四字节字段的二进制 | 采样发现候选词，按它们在当前块的实际频率排名。前 127 个编号占 1 字节，其余最多 256 个占 2 字节。比较含词典的压缩帧与直接压缩帧，保留较小者 | 压缩包随块保存的局部词典 |
| 已识别的 gzip、PNG、JPEG、ZIP、zstd 文件头，或采样未发现足够重复的二进制 | 普通 zstd | 该块的 zstd 帧 |

例如词表排名第一的词条是 ` the`，包含前导空格。在短文本词元模式中，四个字节会变成单字节 `0x80`。解码器用同一编号取回四个原始字节。未命中的字符照原样保存，包括换行、缩进和 Unicode 组合字符。词条编号来自独立校准语料的频率，日常使用不运行模型。[词表来源和重建方法](data/README.md)

二进制词典以当前块起点为基准，每四个字节取一个对齐字段。记录错位或重复出现在其他长度时，普通 zstd 仍可寻找字节串匹配。纯文本识别要求有效 UTF-8，允许制表、换行等常见空白；UTF-16 文件通常进入二进制路径。

## 格式与接口

`.ztok` 是带模式信息的容器。文件头为 `5a 54 4b 01`，每块依次存储模式、原始字节数、zstd 帧长度、可选的四字节词典指纹，以及一个带内容长度和校验和的 zstd 帧。两个长度使用标准小端 base-128 可变长整数。模式 0、1、2、3 分别表示普通 zstd、静态词元、动态词元和共享历史。独立结束标记为 `ff`。解码会检查格式版本、块长、词典指纹、帧校验和、解码长度和结束标记。解压完整容器使用 `ztok d`。

Rust 库提供 `compress` / `decompress` 处理内存数据，以及 `compress_stream` / `decompress_stream` 处理文件和管道。普通 Cargo 构建没有第三方 crate 依赖。
